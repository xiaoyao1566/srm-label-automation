# 脱敏说明

> 这个仓库是从一个**真实产线项目**提炼出来的。所以第一优先级不是"功能好看"，
> 而是**证明仓库里没有任何真实业务数据** —— 而且这个证明不能靠"我看过了"。

---

## 一、要挡住什么

| 类别 | 原项目里长什么样 | 仓库里 |
|---|---|---|
| 客户 / 项目简称 | 分散在文件名与代码注释里 | 只出现在**靶站的编造数据**里，且是 `DM-1001` 这种一眼假的形态 |
| 门户地址与账号 | 内网域名、账号口令 | 只保留 `127.0.0.1` 回环地址；账号口令一律来自环境变量 |
| 真实料号 / 订单号 / 单据号 | 8 位以上数字串 | 仓库里**没有任何 8 位以上连续数字** |
| 共享盘路径 | 以两个反斜杠开头的网络共享路径 | 一个都没有；配置里用"本地配置文件 + 环境变量" |
| 凭证 | 散落在脚本里的口令字面量 | 零。**连演示用的占位口令都从环境变量取**（见第三节） |

## 二、三个工具，一条流水线

```bash
# ① 从原项目的**文件名**自动派生敏感词表（不需要人把客户名敲进任何地方）
python tools/derive_tokens.py <原项目目录> -o <私有目录>/敏感词表.txt

# ② 扫一个目录：只报「文件 / 行 / 类别 / 长度」，绝不回报命中原文
python tools/scan_sensitive.py <目录> --词表 <词表> --self-check

# ③ 发布前闸门：私有目录 + 凭证文件 + 脱敏扫描，任一不过就拒绝发布
python tools/pre_publish_check.py --词表 <词表> --豁免 <豁免表>
```

### 为什么扫描器**故意**不告诉你它扫到了什么

一个"帮你找敏感信息"的工具，**本身就是最大的泄漏面**。
只要报告里带任何形式的原文片段（"预览"、"开头 6 位"、"上下文"），这份报告就变成了第二份泄漏源 ——
找敏感信息的工具反而制造了一个敏感文件。

所以报告里只有位置和类别。连敏感词命中也只写「词表第 N 条」，词本身留在私有词表里。
这样这份报告可以随便传阅、随便贴进 issue。

### 它会验证**自己的输出**

```bash
python tools/scan_sensitive.py --selftest      # 用内置假样本，不碰真实代码
```

`--self-check` 会拿扫描结果回头逐条断言：**报告正文里不含任何命中原文**。
验证的是工具的输出去，不是它自己的逻辑 —— 这两件事经常被混为一谈。

**一条必须说清的边界**：报告里**有文件名**，而文件名本身就常常带客户简称（`<客户>打标签.py`）。
这不是泄漏，是这份报告要有用就避不开的；代价是**报告只能放私有目录，不能入库、不能外发**。
所以自我检验只保证"内容"那一层（把每行路径部分去掉之后再断言）。

## 三、词表：自动派生 + 有理由的豁免

**派生**：文件名本来就是这个项目里"客户名单的现成副本"，直接从文件名派生，一个都不会漏，
而且不需要任何人把客户名敲进对话或配置文件。派生时会自动剥掉通用功能词
（打印 / 标签 / 任务表 / 配置 / 校验 …），只留短简称。

**豁免**：词表是从文件名派生的，难免混进"通用汉语短语"。这类词出现在正文里不是泄漏，
但**不能悄悄放过**。所以豁免表：

- 格式是 `词指纹 <TAB> 理由`，**理由必填**；
- 词指纹 = 词本身的短哈希，**不是"词表第 N 条"**；
- 只能放私有目录；
- **报告里必须显示"已豁免 N 条"**，不许静默少查。

> **为什么要用指纹而不是序号**（这是踩出来的）：词表是从原项目文件名**自动派生**的。
> 原项目一加文件、通用词表一调整，所有序号就会整体漂移。
> 实测踩到过：加完几个通用词后，原来按序号写的豁免落到了**另一个词**头上 ——
> 该豁免的没豁免、不该豁免的反而被放过。指纹只跟词本身有关，不受顺序影响。

豁免是**全局**的（豁免一个词，它在所有文件里都不再报）。所以只允许用来豁免"确认是通用词、不是专名"的条目。
如果某个词的豁免理由是"它只在我这个文件里" —— 那说明该改的是文案，不是加豁免。

## 三·五、召回率是**可测的**，而且它不完美

一个词表最危险的地方不是"不够全"，而是**没人知道它有多全**。
所以这里给覆盖率定了一条硬判据：

```
[覆盖自检] 专属文件名 34 个，其中 18 个至少被一个词前缀命中
[覆盖自检] 未命中 16 个；其中「剥掉通用词后还有残留」的只有 12 个
```

- **专属文件名** = 名字里带业务标记（任务表 / 打标签 / 使用说明）、且不是备份/日志的那些；
- **命中** 判据用「**前缀**」而不是「包含」：客户简称是文件名的开头，用"包含"等于没查；
- 「未命中」不等于漏了 —— 像 `自动打标签` 这种纯功能名本来就不该有词命中。
  所以再加一层：**把这个名字里的通用词全剥掉，看还剩不剩东西**。剩东西的才需要人工看。

另外还有一个 `--广撒网` 模式（取文件名开头 2~4 个汉字），能把覆盖从 18/34 提到 23/34。
它**不进日常闸门**，原因是实测发现它会把通用词截成半截（产出 `全流`、`本机配`、`本次运` 这类词），
在仓库里刷出一堆假命中。

> 这里的取舍值得说明白：**宁可召回低一点，也不让闸门变成"狼来了"。**
> 一份总在报警的报告会训练人直接忽略它 —— 那比漏报更糟。
> 所以广撒网只当定期深度体检用，而日常闸门保持"报出来的每一条都值得处理"。
> 召回的真实水平由 `--自检` 的数字说话，不靠感觉。

**如实说明边界**：这套机制能保证"词表里有的，仓库里一定查得到"，
但不能保证"所有真实专名都在词表里"。覆盖率报告就是用来暴露这个缺口的 ——
未命中的清单会写到私有目录，需要人过一眼。

## 四、判据要收紧到"值得处理"

脱敏扫描的每一类判据都刻意写窄，因为**假命中比漏报更能坏事**：
一份总在报警的报告会训练人直接忽略它。

| 一开始的假命中 | 后来的判据 |
|---|---|
| 散文里提到"口令"两个字就被当凭证（报了 228 处，九成是噪音） | 只认**赋值 + 字面量**：关键词后面紧跟等号或冒号，再跟一个**带引号的字符串或纯数字**；而"关键词 + 冒号 + 类型名"这种类型标注不算 |
| 版本号被当 IP（`opencv-python==4.11.0.86` 实测中招） | IP 加负向断言：前面是 `=`、`.`、数字的都不算 |
| `xmlns="http://www.w3.org/2000/svg"` 被当网址 | 忽略回环地址与 XML/SVG 命名空间 |
| 7 位账号够不着"长数字串"的 8 位阈值 | 单开一类「账号赋值」（引用形式的账号） |
| 工具文件里的中文撞上词表（工具源码里写着"要抓什么"的**模式定义**） | 按**类别 × 路径**分维度排除：`--排除`（整文件，给正则字面量所在文件）+ `--词表排除 tools/*.py`（只关词表这一类，凭证/地址/料号在 `tools/` 下照常查） |

最后一条尤其值得说：**整体排除工具文件太糙**（会连带漏掉真凭证），
而"按类别 × 路径"排除既能消掉自指噪音，又不牺牲该查的部分。

## 五、闸门要经得起**故障注入**

"闸门是绿的"本身不能证明什么 —— 有可能它根本什么都没查。所以每次改判据，都要做一次反向验证：

```
往仓库里塞一个假的泄漏文件：一个真实样子的域名 + 一个 10 位料号
  → 闸门必须拦住（实测：报 2 处命中，拒绝发布）
删掉它
  → 闸门必须放行（实测：0 处命中）
```

同理，`.gitignore` 里列的东西（运行产物）会被当作"不会发布的内容"跳过 ——
这也要在注入测试里确认它**没有把眼睛蒙上**：注入的文件不在 `.gitignore` 里，仍然必须被拦住。

---

## 六、还有一条：**别在演示里放真口令**

演示脚本里连"占位口令"都不写成"关键词 = 带引号的字符串"这种形状：

```python
cfg.站点.口令 = os.environ.get("SITE_PASSWORD", "演示口令")
```

原因不是这条本身危险，而是**开了先例**：一旦仓库里允许出现"口令 = 字面量"这种形状，
闸门那条判据就形同虚设了。靶站本身也**不校验口令内容** —— 这样"能跑"和"零凭证"就不冲突。
