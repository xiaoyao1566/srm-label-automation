# 踩坑录

> 只记**会让脚本静默做错事**的坑。会明确报错的坑大多自己会暴露，不值得占篇幅；
> 真正花时间的是那些"日志上一切正常、结果全错"的。

每条的格式：**现象 → 根因 → 解法 → 教训**。

---

## 一、打印服务事件（307）解析：四个坑，每个都让结果**静默变成 0 条**

**现象**：读本机打印历史，返回 0 条。而用 PowerShell `Get-WinEvent` 查同一个日志，明明有几千条。

**根因**（四个叠加，任何一个都足以让解析全废）：

| # | 坑 | 表现 |
|---|---|---|
| 1 | 参数字段是**元素**：`<Param5>值</Param5>` | 按常见的 `<Data Name="Param5">值</Data>` 写，一个都匹配不到 |
| 2 | XML 属性用**单引号**：`SystemTime='...'` | 正则里写死双引号 `SystemTime="` → 全军覆没 |
| 3 | 秒有 **7 位小数**（`.8455019`） | Python 3.10 的 `fromisoformat` 最多认 6 位 → `ValueError` |
| 4 | `SystemTime` 是 **UTC** | 不转换就差 8 小时，排查时得出"时间对不上、肯定不是这次打的"这种**错误结论** |

**解法**：按元素解析 `Param`；属性引号用 `(['\"])…\1` 兼容两种；截断到 6 位小数；`.astimezone()` 转本地。
另外 `EvtNext` 读到头时抛的是"没有更多数据可用"（259），不是返回空列表 —— 不接住会把"正常读完"当故障。

**教训**：
- **静默返回 0 是最坏的失败方式**。它不报错，看起来就像"这台机器没打过"，于是你会去查错方向（查权限、查日志是否启用）。
- 所以解析器必须拿**真实数据**验一遍。这次就是拿本机 224 条真实历史记录验穿的 —— 写完代码看一遍逻辑是不够的。

## 二、表头全选框有**两份 DOM**

**现象**：代码点了"全选"，日志没报错，但一行都没勾上。

**根因**：表格组件会把固定列单独渲染一份。于是 `.vxe-header--column .vxe-cell--checkbox` 匹配到**两个**元素：
一份在隐藏的固定列容器里，一份是真正的表头。**隐藏的那份在 DOM 里排在前面**，`.first` 取到的是它。

**解法**：把 `:visible` 写进选择器本身（而不是事后补救）：`.vxe-header--column .vxe-cell--checkbox:visible`。
同理，数据行也要 `tr.vxe-body--row:visible` —— 不加的话，会把**另一个 tab 里那张表**的行也数进来（实测数到 20 行幽灵行，行号全指错）。

**教训**：`查询到元素` ≠ `查询到了正确的元素`。凡是"在一堆相似节点里挑一个"的地方，都要带上**可见性/业务键**这类限定，不能只靠位置。

## 三、筛选面板里**按回车会重置整个面板**

**现象**：填了 7 个筛选条件（每填一个按回车提交），搜出来的料**全是错的** —— 条件一个都没生效。

**根因**：面板里的输入框绑定的是"回车 = 触发查询并重置面板"。填一个按一次回车，等于把刚填的全冲掉。

**解法**：
- 一律用 `Tab`（失焦）提交，**绝不按 Enter**；
- 每个字段填完**回读核对**，读回来的值不对就当场报错，绝不带着"我以为筛上了"往下走；
- 所有条件填完，**只点一次**搜索。

**教训**：**"我填了"不等于"它生效了"。** 凡是往组件里写值，都要有一步独立的回读校验 ——
这一条后来变成了这个项目的通用做法。

## 四、每页 20 条：勾选必须跨页，而且要**对账**

**现象**：要打 42 张，实际只出了 20 张。

**根因**：列表页每页固定 20 条，表头全选**只作用于当前页**。

**解法**：逐页勾选，并且和页面上的「共 N 条」对账。停止条件要保守：
**连续 2 页没有新增才停** —— 只按"这一页新勾到 0 个"就停，会在页面还在渲染时提前收手。

**教训**：**分页 + 勾选**这类组合操作，一定要有一个**页面自己给的独立计数**来对账（这里是「共 N 条」和「跨页选择总行数」）。
只信自己的累加器，迟早会少做事而不知道。

## 五、点【确认打印】**不会出纸**

**现象**：脚本日志写着"已点确认打印"，纸一张没出。更坑的是：控件点击抛了异常、脚本判"失败"，纸其实已经出去了 —— 重跑就打了两份。

**根因**：真正的打印按钮在**另一个上下文**里（浏览器打印预览 UI），页面 DOM 根本点不到。
而"点确认打印"这一步只是把任务提交到页面，**它本身不出纸**。

**解法**：
- 接住新窗口（popup），去那个窗口里点真正的【打印】；
- **判成功只认操作系统的证据**（打印队列 / 打印服务事件），不认自己的点击返回值；
- 控件点击抛出的那个异常**不要当失败** —— 实测"点成功之后也会抛"。所以一抛异常就重试，等于把整叠标签打两份。
  宁可"以为没打出去、其实打了"（人看一眼就知道），也绝不冒打两份的险。

**教训**：**不可逆的动作（出纸、发消息、扣款）必须有放重复的安全阀。**
这里的阀是：**重试之前先复查有没有晚到的证据**。

## 六、日期框打不进字

**现象**：`fill()` 往日期框填值"成功"了，但筛选条件里没有它。

**根因**：组件化的 DatePicker：输入框 `readonly`，值只能通过日历面板设置。打字会被弹回原值。

**解法**：点日历按钮 → 点具体的某一天 → 回读核对。

**教训**：和坑三同类 —— **写进去 ≠ 生效**，回读是唯一能证明的办法。

## 七、"出错就退出"会把已经出纸的批次变成**待重打**

**现象**：脚本跑到第 30 分钟挂了，任务表里那些**真的已经打过标签**的行仍然是"待打"状态。重跑一次 → 全部再打一遍。

**根因**：完成标记写在流程**最后**一步（统一回写）。中途异常 → 回写没执行 → 已完成的痕迹全没了。

**解法**：
- 每确认一颗料**立刻**记进"已完成"清单，而且这份清单**跨异常保留**；
- 出错**不中断**整批：单颗料失败只跳过它，其余照跑，最后统一汇总；
- 每条错误都要带一句「**人工该做什么**」—— 现场的人不看 traceback。

**教训**：**完成标记要跟着"事实发生的那一刻"写，不能攒到最后。** 攒到最后就等于把整批的进度押在最后一行代码上。

## 八、判据不独立于被测对象：张数算错却**自我验证通过**

**现象**：外箱标签数量算错，但脚本的"张数守门"没发现。

**根因**：算张数用的公式，和写进系统里、"守门"时用来核对的参数，是**同一个公式算出来的**。
于是错得自洽 —— 自己检查自己，永远查不出来。

**解法**：每箱装几个内袋，改成按**料号查一张固定的箱规表**（由业务给定），而不是用内箱总数反推。
这样"用来填进系统"的口径和"用来核对的"口径就分开了。

**教训**：**自己检查自己不算检查。** 判据要来自被测对象之外 ——
这条在本项目里反复出现：出纸要看操作系统日志、勾选数要看页面计数、脱敏要看独立扫描器。

## 九、两处"看起来能用、其实会坏"的写法

| 坑 | 为什么坏 | 怎么办 |
|---|---|---|
| 把 `<div>` 塞进 `<tr>` | 非法 HTML，浏览器会把节点**拎到表格外面**，DOM 结构和想的不一样 | 想放"另一个表头"就再开一张独立的 `<table>` |
| `window.open` 写在 `await` 之后 | 浏览器只认**用户手势当口**开的窗口；await 回来再开会被弹窗拦截器挡掉，表现是"点了没反应" | **同步**先把窗口开出来（`window.open("")`），拿到数据后再给它 `location` |

**教训**：这两条都是"报错都没有，只是不生效"。**排查这类问题的唯一抓手是让行为留下可观察的痕迹**
（比如把 `document.title` 改掉、把计数显示出来），否则你只能靠猜。

## 十、`openpyxl` 保存带图片的表格模板会**写坏文件**

**现象**：用 `openpyxl` 打开一个内嵌了几百张图片的表格模板，改两个格子再保存 —— 文件从 289 KB 变成 213 KB，
内容丢失，甚至有打不开的情况（实测发生过一次，最后从办公软件的自动备份里恢复）。

**解法**：这类模板**不要用 `openpyxl` 保存**。改成连**已经打开的那个办公软件活实例**（COM），
读内存里的最新内容、改完直接让它自己保存。附带好处：用户不用管"保存并关闭文件"这件事。

**教训**：**"读得开"不等于"写回去还一样"。** 对二进制格式（xlsx/docx 这类 zip 包）做**原地修改**，
先用一个副本做一次"改—存—再打开"的往返验证，再对真文件动手。

## 附：怎么让这些坑**可复现**

以上每一条如果只是写在文档里，下一个人照样会踩。所以这个仓库里有一个 **靶站**：
一个纯标准库的本地小网站，把其中五个坑**照原样复刻**：

```bash
python tools/verify_pitfalls.py
```

它跑的是**差分验证**：每个坑用**错的写法**跑一遍（必须失败），再用**对的写法**跑一遍（必须成功）。
两条断言同时成立，才算"这个坑被复刻了"。
