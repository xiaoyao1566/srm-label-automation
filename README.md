# 供应商门户标签自动化 · 可复现演示

> 一个"网页自动化 + 打印出纸"的完整工程样例。
> **clone 下来一条命令就能跑通**，不需要真门户、不需要打印机、不需要任何真实业务数据。

---

## 一、它解决什么问题

制造企业的仓库每天要按送货单，在客户/供应商的门户上**逐颗料建标签、筛出刚建的标签、勾选、打印**内外箱标签，再把结果记回表格。

纯手工做这件事的痛点是**量**和**错**：

- 一颗料要在网页上填六七个字段，填错一个 → 打出来的标签是错的 → 整批返工；
- 列表页每页固定 20 条，**勾选必须跨页**；只勾当前页就打印，会静默少打；
- 最大的坑是**"以为打出去了"**：脚本报成功、日志写着成功，纸其实一张都没出。

这个仓库把这件事做成了一个分层清晰的小系统，并且把当时踩过的坑**在本地靶站里复刻出来**，让任何人都能自己验证"错的做法会怎么坏、对的做法为什么对"。

## 二、一条命令跑起来

```bash
pip install -r requirements.txt
python demo/run_demo.py
```

演示脚本会自己把靶站起起来（纯标准库的小网站），然后跑完一整条链路：

```
登录 → 进列表页 → 展开高级查询 → 填条件（含点日历选日期）→ 搜索
     → 跨页全选 → 提交打印 → 接住"打印预览"新窗口 → 点真正的【打印】
     → 读【出纸记录】证明它真的出纸了
```

实测输出（本机）：

| 步骤 | 耗时 |
|---|---|
| 打开系统 + 登录 + 进列表页 | 2.2 秒 |
| 第一轮填筛选（冷启动，6 个字段） | 1.0 秒 |
| 第二轮只改料号（**值记忆**生效） | 0.3 秒 |
| 跨页全选（42 行 / 3 页） | 0.7 秒 |
| 提交打印并等到出纸证据 | 0.3 秒 |

```bash
python demo/run_demo.py --有头     # 显示浏览器窗口（录屏用）
```

## 三、架构

```
┌──────────────────────────────────────────────────────────┐
│  demo/run_demo.py          把下面这些串成一条业务链路      │
└───────────────┬──────────────────────────────────────────┘
                │
   ┌────────────▼─────────────┐   ┌──────────────────────┐
   │ src/engine/  通用内核     │   │ mock_srm/  靶站      │
   │                          │◄──┤ 纯标准库、零依赖      │
   │ config   会变的东西       │   │ 复刻 5 个真坑        │
   │ logkit   出错不中断+指引  │   └──────────────────────┘
   │ pages    起浏览器/登录    │
   │ panel    筛选面板(Tab)    │   ┌──────────────────────┐
   │ table    表格与跨页勾选   │◄──┤ 证据源（同一个接口）  │
   │ printing 提交+判出纸      │   │ ① 307 打印服务事件    │
   │ evidence 出纸证据 ★       │   │ ② 打印队列            │
   └──────────────────────────┘   │ ③ 模拟源（无打印机）  │
                                  └──────────────────────┘
```

**分层的一处刻意设计**：`evidence` 定义了一个证据源接口，真实实现（读 Windows 打印队列与打印服务事件）和模拟实现**走同一条代码路径**。
所以"没打印机就跑不了"这件事被消掉了 —— 而"判出纸"的那几行代码一个字都不用改。

## 四、五个真坑（都做了差分验证）

靶站不是"长得像"，是**错的写法必定失败**。验证：`python tools/verify_pitfalls.py`

| # | 坑 | 错的写法会怎样 | 对的写法 |
|---|---|---|---|
| ① | 表头全选框有**两份 DOM**（固定列那份是隐藏的，且排在前面） | `.first` 取到隐藏那份 → 点击超时 / 点了没反应 | 选择器里带 `:visible` |
| ② | 筛选面板里**按回车会重置整个面板** | 填了 7 个条件按回车 → 条件全丢，结果变成全表 | `Tab` 失焦提交 + **回读核对** |
| ③ | 每页固定 20 条，全选**只作用于当前页** | 只勾当前页 → 42 条只打 20 条（静默少打） | 逐页勾 + 和「共 N 条」对账 |
| ④ | 点【确认打印】**不会出纸**，真按钮在另一个窗口里 | 以为成功了，纸一张没出 | 接住 popup，在预览窗口里点【打印】 |
| ⑤ | 日期框 `readonly`，组件化的 DatePicker | `fill()` 打字会被弹回，条件静默失效 | 点日历挑日期 |

实测（本机）：

```
坑① 错法：TimeoutError，勾选数 0      ✔ 必须失败
坑① 对法：勾选数 20                    ✔ 必须成功
坑② 错法：回车后框值为空、结果 42 条   ✔ 必须毁掉条件
坑② 对法：Tab 提交后 6 条              ✔ 必须筛对
坑③ 错法：只勾当前页得 20 / 共 42 条   ✔ 必须少勾
坑③ 对法：勾到 42 = 共 42 条           ✔ 必须勾满
坑④ 错法：点完【确认打印】出纸记录 0   ✔ 必须不出纸
坑④ 对法：预览里点【打印】→ 记录 1 条  ✔ 必须出纸
坑⑤ 错法：往日期框打字 TimeoutError    ✔ 必须失败
坑⑤ 对法：点日历后框里值正确          ✔ 必须成功
```

## 五、最值钱的一条：**判据必须独立于被测对象**

脚本说"打印按钮已点: True" **不算证据**。实测翻过车：日志写着成功，打印服务事件里一条记录都没有 —— 一张纸都没出去。
更早还有反过来的：点击抛了异常、脚本判"失败"，纸其实已经出去了 —— 于是重跑，**整叠标签打了两份**。

所以这里只认**操作系统给的说法**：

| 证据源 | 拿到什么 | 特点 |
|---|---|---|
| 打印队列 | 任务**进队**的瞬间 | 最快（约 0 ms），但排空之后就没痕迹了 |
| 打印服务事件（307） | 任务**真的打到打印机** | 最权威（约 2 ms 读一次），但**比提交晚** |

两者一起用，因为**它们覆盖的时间点不同**。这里有一条必须记住的边界：

> 307 事件是**整个打印服务**的事件，**不带料号**。
> 所以"水位线之上有新的 307"只能证明**有东西出纸了**，不能证明是**这一批**。
> 内箱几十张还在打的时候去查外箱，必然能查到内箱的事件 —— 判成"外箱也成功了"。
> 正确做法：**先用队列排空 + 水位线把范围框住**；排空不了就只认队列、不认事件。

还有一条安全阀值得单独说：**自动重试之前，必须先复查有没有"晚到的证据"。**
纸已经出去了、证据还没落地 —— 这时重试就是打两份。前者可恢复，后者是废纸加停机。

## 六、验证套件

```bash
python tools/verify_evidence.py     # 出纸证据：19 项
python tools/verify_pitfalls.py     # 靶站差分验证：10 项
python tools/pre_publish_check.py   # 发布前脱敏闸门
```

`verify_evidence.py` 分两半，**两半都验**：

- **真实数据那半**：拿本机真实的 307 历史记录验解析器（实测读到 224 条）。全程只读，不出纸。
  这一步非做不可 —— 解析器最阴的失败是**静默返回 0 条**：不报错、不提示，看起来就像"这台机器没打过"。
  实际踩到四个坑（详见 `docs/pitfalls.md`）：参数字段是元素不是属性、XML 属性用单引号、秒有 7 位小数、时间是 UTC。
- **判据那半**：用注入的方式验"零证据必须判失败""晚到证据必须拦住重试"等时序，这些没法靠真打印机复现。

## 七、脱敏：怎么保证仓库里没有真实业务数据

这个仓库是从一个真实的产线项目里提炼的，所以"会不会带出真数据"是**第一优先级**，而且**不靠人眼看**：

```bash
python tools/derive_tokens.py <原项目目录> -o <私有目录>/敏感词表.txt   # 从文件名自动派生客户/项目简称
python tools/scan_sensitive.py <目录> --词表 <词表> --self-check        # 只报位置，绝不回报命中原文
python tools/pre_publish_check.py --词表 <词表> --豁免 <豁免表>          # 发布闸门：不过就不许发布
```

三条设计原则：

1. **扫描器自己不能成为泄漏源**。它只报「文件/行/类别/长度」，**不含任何命中原文** —— 连"预览片段"都不给。
   敏感词命中也只写「词表第 N 条」，词本身留在私有词表里。
   它还会 `--self-check`：扫完回头逐条断言"报告正文里不含命中原文"，**验证的是自己的输出，不是自己的逻辑**。
2. **词表自动派生**，不需要人把客户名敲进任何地方；派生时会自动过滤通用功能词。
   极少数漏网的通用汉语短语走**带理由的豁免表**，而且报告里必须显示豁免了几条 —— 不许悄悄少查。
3. **闸门要经得起故障注入**。往仓库里塞一个假的泄漏文件（一个真实样子的域名 + 一个 10 位料号），
   闸门必须拦住；删掉它必须放行。这条验证每次改判据都会重跑一次。
4. **召回率是可测的数字，不是感觉**。词表带一个覆盖自检：客户专属文件名里有多少个一个词都没命中，
   以及其中多少个"剥掉通用词后还剩东西"（那才是真需要人看的）。
   实测当前是 **34 个专属文件名覆盖 18 个、待人工 12 个**；开了 `--广撒网` 能到 23/34，
   但它会把通用词截成半截、刷出假命中，所以只当定期体检用 ——
   **宁可召回低一点，也不让闸门变成"狼来了"。**

判据的收紧本身也有讲究：**假命中比漏报更能坏事**。
一开始"凭证"这一类报了 228 处，九成是散文里提到"口令"两个字 —— 那种报告没人会看第二眼。
收紧到"赋值 + 字面量"之后剩下个位数，每一条都值得处理。
（同类收紧还包括：版本号不能被当成 IP、`xmlns` 命名空间不算网址、`口令: str = ""` 这种类型标注不算凭证。）

详见 [`docs/desensitization.md`](docs/desensitization.md)。

## 八、边界（如实说明）

- **靶站是替身，不是真门户**。五个坑是照着真机行为复刻的，但真机还有更多业务规则（多账号、分批到货、模板回写等）没有搬进来。
- **演示用的是模拟证据源**。真实路径（打印队列 + 307 事件）已用本机真实历史数据验证过解析与过滤，
  但"真的出一张纸"这一步没有在演示里跑 —— 那要占用真打印机，不该由演示脚本替你做决定。
- **真实项目里的收益数字没有放进仓库**：那些数字和客户数据绑在一起，脱敏时一并去掉了。
  仓库里保留的都是**你在这台机器上能自己复现**的耗时与断言结果。
